# Docker Stack Naming Drift Fix

Date: 2026-04-22
Repo: `/var/llamaindex/ghoststack-rag`

## Issue

Runtime diagnostics were sometimes attempted with legacy container names:

- `ghost-edge-gateway`
- `ghost-control-plane`

Those names do not belong to the current GhostDASH stack. The live stack is generated by Docker Compose project name `ghoststack-rag` plus current service names such as `caddy`, `control-api`, and `agent-ingress`, which yields containers like:

- `ghoststack-rag-caddy-1`
- `ghoststack-rag-control-api-1`
- `ghoststack-rag-agent-ingress-1`
- `ghoststack-rag-workflow-runtime-1`

## Root cause

The repo contains historical Odoo handover material under `artefacts/odoo_bundle_reference/...` from an older stack shape. Those references were being mentally reused during diagnostics even though the active compose file defines different service names.

The live `docker-compose.yml` is internally correct and renders the current project name as:

```bash
docker compose config
```

Expected first line:

```text
name: ghoststack-rag
```

## Fix applied

1. Added `scripts/stack_diagnostics.sh` as the canonical way to resolve current diagnostics targets from `docker compose ps`.
2. Updated `docs/OPERATIONS.md` to explicitly mark `ghost-edge-gateway` and `ghost-control-plane` as legacy names for this repo.
3. Kept live service/container naming unchanged to avoid unnecessary runtime and routing churn.

## Why this is the right fix

Renaming the actual containers would introduce needless drift and risk:

- internal service DNS already uses `control-api`, `agent-ingress`, `workflow-runtime`
- docs and current runbooks already reference `ghoststack-rag-*`
- Compose-generated names are deterministic from the current project and service definitions

The correct repair is to stop hardcoding stale names and derive the current names from Compose.

## Acceptance criteria

- `./scripts/stack_diagnostics.sh` prints the live compose project name and resolved container names.
- `docs/OPERATIONS.md` identifies the canonical `ghoststack-rag-*` diagnostics targets.
- No Docker service rename or runtime redeploy is required to make diagnostics correct.

## Exact verify commands

```bash
cd /var/llamaindex/ghoststack-rag
git status -sb
docker compose config
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}\t{{.Status}}'
./scripts/stack_diagnostics.sh
```
